# Step 5 — Understand `decode_token`

The relevant ARM64 instructions are:

```text
ldrb
mov ... 0x5a
eor
strb
```

The important instruction is:

```text
eor
```

`EOR` is ARM64's XOR operation.

The function essentially does:

```text
encoded_byte XOR 0x5A
```

for every byte.

So:

```text
g_token_enc
     ↓
XOR every byte with 0x5A
     ↓
decoded text
     ↓
UUID
     ↓
USER FLAG
```

The walkthrough explicitly states that the decoded 36-byte result is the user flag. 

### Important lesson

This is why simply running:

```bash
strings sentinel-activate
```

may not reveal the flag.

The flag is **obfuscated**.

# Step 8 — Understand ×27

The Python implementation from the walkthrough represents multiplication by 27 as:

```text
(c << 1) + c
```

That gives:

```text
c × 3
```

Then:

```text
(c << 3) + c
```

That gives:

```text
c × 9
```

Together:

```text
3 × 9 = 27
```

So:

```text
c × 27
```

The source walkthrough explicitly shows this implementation. 

---

# Step 9 — Add 61

Next:

```text
c = c + 61
```

The implementation uses:

```python
(c + 0x3d) & 0xFF
```

because:

```text
0x3d = 61
```

and:

```text
& 0xFF
```

keeps the result within one byte.

---

# Step 10 — XOR with 71

Next:

```text
c = c XOR 71
```

In hexadecimal:

```text
71 decimal = 0x47
```

So the Python representation is:

```python
c ^ 0x47
```

The walkthrough explicitly documents this operation. 

---

# Step 11 — Add the character index

Next:

```text
c = c + i
```

Where:

```text
i = character position
```

For:

```text
admin
```

the indexes are:

```text
a → 0
d → 1
m → 2
i → 3
n → 4
```

So the first character gets:

```text
+0
```

the second:

```text
+1
```

and so on.

---

# Step 12 — XOR with account length

`admin` contains:

```text
5 characters
```

Therefore:

```text
name_len = 5
```

Each transformed character is then:

```text
c XOR 5
```

The walkthrough confirms that the account-name length is used in this operation. 

---

# Step 13 — Put the result into the 6-byte buffer

This is the clever part.

The program has:

```text
buf[0]
buf[1]
buf[2]
buf[3]
buf[4]
buf[5]
```

Initially:

```text
0 0 0 0 0 0
```

For each character:

```text
buf[j] = buf[j] XOR c
```

Then:

```text
j = j + 1
```

When `j` reaches 6:

```text
j = 0
```

So the position **rotates**.

The walkthrough calls this a:

> rotating 6-byte buffer



---

# Step 14 — Convert the buffer to hexadecimal

After all characters are processed, we have:

```text
6 bytes
```

Each byte becomes:

```text
2 hexadecimal characters
```

Therefore:

```text
6 × 2 = 12 hex characters
```

Example structure:

```text
A1B2C3D4E5F6
```

The program then formats those 12 characters as:

```text
SENT-A1B2-C3D4-E5F6
```

The walkthrough confirms this final format.

# Step 16 — The KeyGen algorithm

Your separate `KeyGen.py` should implement:

```text
1. Create 6-byte buffer
2. Get account length
3. Loop through characters
4. Convert character → ASCII
5. ×27
6. +61
7. XOR 71
8. + character index
9. XOR account length
10. XOR into buffer[j]
11. Rotate j
12. Convert buffer → hexadecimal
13. Format as SENT-XXXX-XXXX-XXXX
```

This is directly supported by the walkthrough's documented algorithm.
